# 认证与会话授权修复

**更新日期：** 2026-11-04

**更新范围：** 安全审计 A01、JWT 认证、会话撤销、用户权限读取及对应隔离回归测试。

## 问题与修复

原有 `AuthService::decryptAuthData()` 会把 JWT 对应的用户和角色缓存一小时，命中后跳过验签、会话检查和用户查询。删除单个会话后，旧 JWT 仍可命中授权缓存；管理员被降权后也可能在缓存有效期内继续操作后台。由于缓存键直接使用传入凭据，普通缓存项还可能绕过 JWT 验证。

- 每次认证都执行 HS256 验签并校验必要声明的结构，然后确认 JWT 对应的会话仍存在。
- 每次认证从数据库主库读取用户当前状态和角色，用户不存在或已禁用时拒绝认证，管理员和员工降权即时生效，避免只读副本延迟使旧权限继续有效。
- 不再使用 JWT 对应的用户与角色缓存，也不接受命中普通缓存项的非 JWT 字符串作为登录凭据。
- 删除单个会话时同时清理该会话遗留的 JWT 授权缓存，避免形成无法通过会话目录枚举的孤立缓存。
- 按用户对新增、删除单个及清空会话加互斥锁，避免并发读写会话目录时将已撤销会话写回。锁等待超时则操作失败；登录未能保存会话时返回 503，不签发可用的登录结果。
- 补充隔离回归测试，验证真实认证服务及用户、员工、管理员中间件的拒绝行为。

本次以每次请求增加一次用户查询为代价，保证权限以当前数据库记录为准，避免角色缓存与撤权状态不同步。会话仍保存在原有缓存中，无需增加数据库字段或迁移；格式正确、签名有效且仍有对应会话的既有 JWT 可以继续使用。

即时生效指撤销或权限变更成功后开始认证的新请求使用最新状态；已经通过认证的在途请求不在此处追溯取消。

后台重置密码和快捷登录码的统一失效属于审计 A02，需要另行修复；本次未改变这些流程。完整问题背景见 [安全审计报告](../security/2026-11-04-full-chain-security-audit.md)。

## 部署说明

按[更新文档](../update.md)同步代码后，重启提供请求的 PHP 服务，并在启用 Webman 时重启对应进程，使全部请求加载新代码。混合运行新旧进程时，旧进程仍可能执行原有缓存授权逻辑，应完成所有实例的切换。

新代码不再信任旧 JWT 授权缓存，因此无需全量清空 Redis 或应用缓存。保留原有会话缓存可让仍有效的登录继续使用；全量清理缓存会使这些会话失效。

会话操作使用缓存原子锁，现有 Redis 部署无需增加设施，框架的 file 和 array 缓存驱动也支持锁。自定义缓存后端必须提供锁支持；配置中保留的 apc 驱动不支持该锁，不能用于这套会话写操作；database 驱动还要求 `cache_locks` 表，项目没有提供该表，建议继续使用 Redis。多实例须使用共享缓存及共享锁，不能各自使用独立的 file/array 缓存。

锁租期为 10 秒，最多等待 5 秒；互斥以会话目录的缓存读写在租期内完成为前提。锁超时导致登录或会话管理操作失败时，应检查缓存服务和并发情况。

完成切换后，建议在隔离验收环境用已登录的管理员账户核对撤权结果：删除会话后旧 JWT 应立即被拒绝；取消管理员角色后，原 JWT 应无法访问后台或恢复自身管理员身份。部署与实际运行环境的验收结果应单独记录。

## 验证范围

新增 `tests/Unit/AuthSessionSecurityTest.php`，使用隔离数据库和缓存验证以下场景：

- 合法既有 JWT 和会话正常使用；缺失用户、禁用用户及缺失会话被拒绝。
- 已预热旧授权缓存的单个会话被删除后立即失效，随后全量注销也不能恢复该会话。
- 管理员或员工被降权后，原 JWT 无法继续通过对应权限中间件；管理员无法借旧缓存恢复自身权限。
- 非 JWT 缓存键、无效签名和声明结构异常不能通过认证，旧 JWT 授权缓存不能覆盖当前用户状态。
- 保留历史 JWT 的合法整数或数字字符串用户 ID，以及未携带 `iat` / `exp` 的既有格式；JWT 中自带的角色声明不能覆盖数据库角色。
- 模拟会话锁等待超时，验证三种会话写操作不改动原会话，登录返回 503。

本地定向回归已通过：**30 项测试、180 条断言**。测试使用内存 SQLite 和 array 缓存，不加载站点 `.env`，不连接真实数据库或外部服务；锁超时使用模拟对象验证，尚不代表完成了 Redis 多进程并发或线上部署验收。

同一组测试在独立进程预载旧版 `AuthService` 时出现 **25 项失败、0 错误**，说明可以检出原有授权缓存问题。完整 Unit 套件通过：**188 项测试、1369 条断言，0 失败、0 错误，1 跳过、13 个弃用提示**；跳过项需要 Linux `/proc/meminfo`，弃用提示来自现有本地 Curl 依赖。

本次执行环境为 Windows / PHP 8.4.27，本地已安装的 Laravel 12.70.2、PHPUnit 11.5.57 与锁文件中的 Laravel 13.40.0、PHPUnit 13.4.6 不一致。没有改动依赖或锁文件；与生产锁文件一致的 Linux / Redis 复核应在部署验收中补充。两个离线审计脚本也已通过，A01 项改为安全拒绝预期，仍保留 A02 等未修问题的观测。
