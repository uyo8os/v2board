# 提前开启记录

日期：2026-11-05。未部署。

- 管理端“工单管理”下新增“提前开启记录”，六列依次为时间、邮箱、订阅、扣除天数、原到期时间、新到期时间。按最新记录排序，支持分页、完整邮箱精确搜索与手动刷新。
- 仅成功提前开启时写入一条 `v2_traffic_advance_log`，保存操作时的邮箱、订阅名称和前后到期时间。后续修改或删除账户、套餐不改变历史记录；不追溯补造已有操作。
- 扣除时长保存准确秒数；页面按 86400 秒折算天数，最多保留六位小数，悬浮查看准确秒数。
- 账户条件更新与记录插入放在同连接短事务中，任一步失败整体回滚。事务内只有两次写入，无显式行锁、自动重试、外部调用或新后台任务，沿用原 1 秒 MySQL 行锁等待限制。
- 列表接口为 `GET /api/v1/{后台路径}/trafficAdvance/fetch`，仅管理员可访问；参数 `current`、`pageSize`、可选 `email`，默认第 1 页、每页 10 条，最多 100 条。邮箱查询使用 `(email,id)` 索引。
- 清理按钮确认后调用 `POST /api/v1/{后台路径}/trafficAdvance/clear`，仅管理员可用。按可选完整邮箱选最旧的最多 1000 个 ID，再单次主键删除；不受分页影响，不自动循环。返回实际删除条数，后续新写入的记录不会被这次已选定 ID 的删除带走。
- 历史记录不参与提前开启或重置判断，清理不会修改账户、流量、到期时间、个人排期或套餐。删除的是查询历史，不能恢复已清理的记录；空邮箱表示所有邮箱。删除仍有数据库隐式锁，只涉及日志表，不对账户加锁。

上线先按现有升级流程执行 `database/update.sql` 创建记录表或给已有记录表补邮箱索引，再发布后端和重新构建的独立管理端。新安装表结构已同步至 `database/install.sql`。未修改节点、用户主题、代理或流量落库逻辑。
