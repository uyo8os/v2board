# 消费限制

日期：2026-11-06。

风控中心新增独立的消费限制，管理员可在人工审核中选择“限制消费”或“解除消费限制”，填写原因并保留审核记录。限制管理按限制类型分别列出记录，用户详情显示原因、操作人和时间；概览的受限账号按用户去重。同一账号的节点限制与消费限制可以同时存在，分别解除，不会互相覆盖。

## 限制范围

- 在用户创建订单前检查消费限制，覆盖套餐新购、续费、变更、充值、流量重置包，以及余额支付和零元订单。受限时返回 HTTP 422，提示“当前账号已限制消费”，不会创建订单或扣除余额。
- 自动续费跳过受限账号，保留原有自动续费设置。解除后按现有续费条件执行，不为已经过期的账号补做自动续费；无法确认限制状态时也跳过本次续费。
- 已有订单的支付、取消和支付回调保持原有处理。礼品卡兑换、提前开启下一周期、佣金内部划转和管理员人工处理不纳入本次限制。
- 查询直接读取数据库，不新增缓存或显式行锁。设置、解除限制与审核记录在短事务中提交；普通数据库写入仍会产生必要的隐式锁。已经通过检查的在途请求可能按原流程完成。
- Kxuw 购买、续费、变更和流量重置包页面共用订单创建入口；充值使用同一后端接口。页面错误区与弹出提示均显示后端返回的具体原因，HTTP 422 不会触发退出登录。

## 数据库与更新

新增 `v2_insider_guard_consumption_restrict`，以用户 ID 为主键，保存操作人、原因和首次限制时间。数据表独立于原节点限制表；设置、解除及审核记录同事务提交，已删除账号的遗留限制由现有风控清理任务清理。

建表语句已同时加入 `database/install.sql` 和 `database/update.sql`。正常全新安装执行 `sh init.sh`，已有站点按 [更新文档](../update.md) 进入维护模式后执行 `sh update.sh`；脚本会自动调用相应 Artisan 命令并创建表，无需再次手动执行 `php artisan v2board:update`。只有手动同步代码且没有运行更新脚本时，才需要按现有升级流程单独执行数据库更新。

发布后端代码，并同步构建发布独立管理端和 Kxuw 主题。主题本次仅调整错误提示，未改动 API 加密协议或代理配置。
