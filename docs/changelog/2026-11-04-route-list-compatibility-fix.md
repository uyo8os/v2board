# 路由查看命令兼容修复

**更新日期：** 2026-11-04

**更新范围：** `route:list` 命令、回归测试和 Docker 运行验收。

## 问题与修复

`route:list` 枚举控制器中间件时，会实例化控制器。项目原有 Telegram Webhook 和部分节点控制器在构造函数中校验请求参数，因此命令行查看路由会触发 `HttpException`。错误输出经 `wc -l` 统计后显示为 6 行，并不代表项目只有 6 条路由。

- 为项目提供兼容的 `route:list` 命令，读取应用路由已声明的中间件，避免为查看路由而执行 HTTP 请求校验。
- 保留框架原有的列表、JSON、筛选等功能；Horizon 等第三方控制器仍按框架原有方式读取中间件。
- 不修改 HTTP 控制器、令牌校验或业务路由。

命令显示应用路由声明的中间件，不展示应用控制器构造函数中动态添加的中间件；实际 HTTP 请求仍执行原有中间件与校验。

## 验证结果

- 新增 3 项回归测试，验证路由查看不会触发 HTTP 校验、真实 HTTP 调度仍会拒绝无效请求，以及第三方控制器中间件信息保留。
- 在 PHP 8.4.27、Laravel 13.39.0 的 Docker 环境中，`route:list` 成功列出 220 条路由，JSON 输出正常，Horizon 认证中间件信息保留。
- 容器内全部 PHPUnit 测试通过：**80 项测试、419 条断言**。
- PHP-FPM 和 Workerman 的真实 HTTP 请求均验证了 Telegram 无效令牌返回 401；登录、订阅、订单、流量、邮件日志传输及审计写入等已有运行验收继续通过。

本次复用了已有隔离验收环境，没有重新执行全新安装或依赖更新。详细记录见 [Docker 验收记录](../../docker/ACCEPTANCE.md)。

## 使用方式

同步包含本修复的代码后，在站点目录执行：

```sh
/www/server/php/85/bin/php artisan route:list
```

路由数量以列表末尾的 `Showing […] routes` 为准，不以终端输出行数为准。实际数量随项目配置和版本变化。
