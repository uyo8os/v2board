# 日志与敏感信息

## 日志来源

管理接口中的系统日志读取 `v2_log`，默认应用日志通道也写入该表。后台 POST 操作会记录固定事件标题和允许的操作标识；数据库日志中可保留时间、级别、请求方法、客户端 IP 和经校验的后台控制器方法。登录凭据、请求参数、完整 URL 及查询串不会作为系统日志数据保存。操作主体和目标 ID 仅在调用方提供正整数时保留；并非所有事件都带这些字段。

队列日志读取 `failed_jobs`，只代表失败作业，不是全部执行历史。Horizon 的失败记录是另一数据源，清空 `failed_jobs` 不会清空 Horizon 的记录。邮件日志记录收件地址、主题、模板和发送错误；没有错误不等于已送达。邮件任务捕获发送异常后仍会写邮件日志，因此不一定进入失败队列。

## 系统日志安全策略

应用配置的 MySQL、daily、single、stack、stderr、syslog、errorlog、Slack 和 Papertrail 通道使用字段白名单。除固定允许的事件标题外，自由文本替换为 `[Log details omitted]`；不保存任意上下文、异常消息及堆栈、请求体或 URL。异常对象只保留类型、文件名和行号；这降低了排障细节，排查时应结合允许保留的事件、级别和时间。新增安全事件标题时，应先确认它是固定文本、不会包含用户输入或凭据，再调整白名单并补充测试。

此策略覆盖上述已配置的应用日志通道，以及 Laravel 日志初始化失败时的 emergency 文件通道；不覆盖按需自建且未配置处理器的通道、第三方自行写入的文件，以及队列失败记录、邮件日志或其他业务表。它也不自动处理反向代理、PHP、容器或外部日志系统记录的数据。各数据源仍可能包含个人信息或敏感内容，应限制访问和备份权限。

## 留存和历史数据

代码修复只作用于新写入的记录，不会追溯清理旧数据。默认调度的 `reset:log` 每日删除一个月前的 `v2_log`；这依赖调度正常运行，且不清理邮件日志、失败队列、外部日志或备份。daily 文件通道配置为保留 14 天，实际删除取决于通道轮转执行情况。系统日志清空接口会清空整张 `v2_log`，不会处理其他来源。

升级前后应按组织留存政策盘点并妥善处置旧数据库记录、日志文件、集中日志和备份，保留需要的审计证据；根据实际暴露范围撤销或轮换密码、令牌及其他凭据。修复部署后重启 PHP-FPM、Horizon 和已启用的 Workerman，让长驻进程加载新代码，并在实际环境核查日志权限及输出。详细变更与验收见 [A11 修复日志](changelog/2026-11-05-system-log-security-fix.md)。
