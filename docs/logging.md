# 日志与敏感信息

## 日志来源

管理后台「系统日志」读取默认应用日志通道写入的 `v2_log`。点击「详情」可查看事件消息和排障上下文。后台 POST 操作记录事件标题、经校验的后台控制器方法，以及调用方提供的正整数主体和目标 ID。数据库日志同时保留时间、级别、请求方法和客户端 IP。

队列日志读取 `failed_jobs`，只代表失败作业，不是全部执行历史。Horizon 的失败记录是另一数据源，清空 `failed_jobs` 不会清空 Horizon 的记录。邮件日志记录收件地址、主题、模板和发送错误；没有错误不等于已送达。邮件任务捕获发送异常后仍会写邮件日志，因此不一定进入失败队列。

## 系统日志详情与脱敏

MySQL、daily、single、stack、stderr、syslog、errorlog、Slack 和 Papertrail 通道保留脱敏后的业务消息和结构化上下文。异常详情包括原因、类型、代码、文件和行号，以及有限的调用栈。调用栈只包含调用位置，不保存参数。数据库异常通过 SQLSTATE 和驱动错误码定位，HTTP 响应异常通过状态码定位。数据库日志写入失败时，daily 文件日志会记录失败原因和原事件。

上述通道及 Laravel 的 emergency 文件通道会过滤敏感字段和可识别的文本凭据。系统日志不会自动附带请求体和 URL 查询串。新增日志时，使用业务消息和必要的结构化诊断字段，避免把未标注的凭据直接拼入文本。按需自建的通道、外部日志、邮件日志、失败队列和其他业务日志由各自的写入逻辑管理。

## 留存和历史数据

代码修复只作用于新写入的记录，不会追溯清理旧数据。默认调度的 `reset:log` 每日删除一个月前的 `v2_log`；这依赖调度正常运行，且不清理邮件日志、失败队列、外部日志或备份。daily 文件通道配置为保留 14 天，实际删除取决于通道轮转执行情况。系统日志清空接口会清空整张 `v2_log`，不会处理其他来源。

升级前后应按组织留存政策盘点并妥善处置旧数据库记录、日志文件、集中日志和备份，保留需要的审计证据。根据实际暴露范围撤销或轮换密码、令牌及其他凭据。修复部署后重启 PHP-FPM、Horizon 和已启用的 Workerman，让长驻进程加载新代码。最初的整改与验收见 [A11 修复日志](changelog/2026-11-05-system-log-security-fix.md)。
